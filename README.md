# Snow Deformation 학습 기록

언리얼 엔진 렌더 타깃 기반 실시간 눈 변형 시스템을 공부하며 정리한 문서입니다.
진행중인 팀 프로젝트에서 구현한 기능 중 일부를 원본 프로젝트에서 별도 프로젝트로 옮겨와 트러블슈팅 기록을 위해 작성 중 입니다.

## 전체 구조 정리

<details> <summary><strong>v0.1 — Additive 블렌드의 한계 → 핑퐁 아키텍처 전환</strong></summary>

머티리얼의 Additive 블렌드 모드로 눈이 파이고 밀려나는 연산을 하나의 렌더 타깃에서 한 번에 처리하려 했습니다.

문제: 캐릭터가 제자리에서 움직이기만 해도 렌더 타깃에 누적되는 값이 무한히 커져 캐릭터가 바닥 아래로 파묻히는 문제가 발생했습니다. 노이즈를 섞은 다이내믹 클램프를 적용했지만, 이번엔 인접 버텍스 간 높이 차이가 극단적으로 벌어지는 Vertex Spiking 현상이 나타났습니다.

해결: 단순 덧셈(Additive) 방식을 버리고, 렌더 타깃 2개를 스왑하며 직전 프레임의 눈밭 데이터를 보존하고 Max 값을 추출하는 핑퐁 구조로 전환했습니다. 값을 무한히 누적하는 대신 프레임마다 최댓값만 갱신하도록 바꾸자 Vertex Spiking 문제가 해결되었습니다.

</details> <details> <summary><strong>v0.2 — 캡처 패스 오버라이트 버그</strong></summary>

새 발자국의 둔덕이 이전에 깊게 파인 부분을 덮어써서 눈이 다시 차오르는 것처럼 보이는 버그를 발견했습니다.

원인: 브러시 머티리얼이 구멍뿐 아니라 옆으로 밀려나는 둔덕까지 함께 그리는데, 새 발자국의 둔덕 부분이 이전 발자국의 깊게 파인 중심부를 덮어쓰고 있었습니다.

해결: 직전 프레임의 렌더 타깃 데이터를 브러시 셰이더에 전달해, 이미 더 깊게 파인 지점은 새 브러시가 덮어쓰지 못하도록 막는 방어 로직을 추가했습니다.

</details> <details> <summary><strong>v0.3 — 눈밭이 여러 개일 때 마지막 볼륨에만 발자국이 찍히는 버그</strong></summary>

맵에 눈밭(Volume)을 여러 개 배치했을 때, 가장 마지막에 생성된 단 하나의 눈밭에만 발자국이 찍히는 버그가 있었습니다.

원인: 서브시스템이 월드의 볼륨을 배열이 아니라 단일 참조 변수로 캐싱하고 있어서, 캐릭터가 1번 눈밭을 밟고 있어도 발자국 데이터가 가장 마지막에 로드된 볼륨으로 전송되고 있었습니다.

해결: 서브시스템이 TArray<ASnowDeformationVolume*>로 모든 볼륨을 추적하도록 바꾸고, 발자국이 찍힐 때마다 좌표(HitLocationWorld)가 어느 볼륨의 영역 안에 속하는지 직접 판별해 해당 볼륨에만 데이터를 전송하도록 구조를 바꿨습니다.

cpp
void USnowDeformationSubsystem::RegisterDeformationPayload(const FSnowDeformationPayload& InPayload)
{
    for (ASnowDeformationVolume* Volume : ActiveVolumes)
    {
        if (Volume && Volume->IsInsideSnowArea(InPayload.HitLocationWorld))
        {
            Volume->RegisterDeformationPayload(InPayload);
        }
    }
}

이 방식으로 바꾸면서, 렌더 타깃 하나로 월드 전체를 덮는 대신 필요한 구역에만 작은 볼륨을 여러 개 배치할 수 있게 돼서 해상도 대비 시각적 밀도도 함께 좋아졌습니다.

</details> <details> <summary><strong>v0.4 — 전체 파이프라인 구조 정리</strong></summary>

기능이 늘어나며 한 번 구조를 정리해봤습니다. 한 프레임 동안의 흐름은 5단계입니다.

이동 추적 — 캐릭터 컴포넌트가 매 틱마다 부위별(발, 종아리 등) 이전·현재 위치를 비교해 눈에 파묻힌 깊이를 계산합니다. 거리가 너무 멀면(텔레포트 등) 스킵하고, 이동 거리가 크면 여러 위치로 보간해 촘촘하게 찍습니다.
데이터 패키징 — 위치·깊이·회전각을 FSnowDeformationPayload로 묶어 서브시스템에 전달합니다.
라우팅 및 대기열 적재 — 서브시스템이 좌표 기반으로 해당 눈밭 볼륨을 판별해 대기열에 쌓아둡니다 (이 시점까진 렌더링하지 않습니다).
일괄 렌더링 (핑퐁) — 대기열 데이터를 렌더 타깃에 한 번에 그려 넣고 Read/Write 버퍼를 교체합니다.
머티리얼 반영 (WPO) — 렌더 타깃 값을 읽어 정점을 밀어내고 노멀을 재계산해 입체감을 만듭니다.

처음엔 발자국 하나 찍는 게 이렇게 단계가 나뉠 일인가 싶었는데, 거리 컬링· 텔레포트 방지·서브 스텝 보간까지 하나씩 필요해지면서 구조가 자연스럽게 여기까지 늘어났습니다.

</details>
